Context and memory in an agent

By the end of this lesson you can say what is in the model's context at each step of the makerspace assistant, what survives between steps and between sessions, and when to use retrieval or notes.

Why this matters for you

Your assistant must answer from long machine manuals, remember each student's training status between visits, and stay inside a small budget. All three are context and memory decisions, and you will defend them at your design review.

Warm-up 1 min

Recall

In the agent loop, after a tool runs, what happens to its result, and who ran the tool?

Check your answer

The program ran the tool, not the model. It then sends the result back to the model as input for the next model call. Today's question is what the model actually sees in that next call.

The context window 2 min

Start with a game. A student asks, "Is the laser cutter free Friday?" The assistant calls check_calendar, then the model writes the answer. Think of an RPG where the game can only draw what fits on the screen. The model is similar: it can only use what is on its "screen" for this call.

That screen is the context window: all the text the model can use when it writes a response, including the response itself. Anthropic calls it the model's "working memory" (Claude docs: context windows). It holds the system prompt, every message so far, every tool result and the tool definitions.

Text is measured in tokens, small chunks of text, roughly word pieces. The window has a token limit, and you are billed by tokens, so a bigger context costs more on every call.

Worked example

Count what the model sees for "Is the laser cutter free Friday, and do I need training?"

  1. Call 1: system prompt and question. The model requests check_calendar.
  2. The program runs the tool. The calendar result is appended to the context.
  3. Call 2: system prompt, question, request and calendar result. The model requests search_manuals.
  4. Call 3: all of the above plus the manual page. The model writes the answer.
  5. The cost: the system prompt was sent three times. Long prompts and long tool results are paid for again on every later call.
A common mix-up

"The model remembers the earlier steps by itself." It is tempting because chat feels continuous. In fact, the model keeps nothing between calls: the program rebuilds the context each time. If a result is not in the context, the model cannot see it.

Check yourself

The assistant's third model call in a run has a calendar result in its context. Why?

Show the answer

The third option: the program carries the history forward and re-sends it.

Between steps and between sessions 2 min

Within one run, the context carries every step forward, so the model sees its earlier tool results. That is the short-term memory: the context itself.

A new session starts with an empty context. Whatever the student told the assistant last week is gone unless your program saved it somewhere and loaded it back. That saved record is long-term memory: it lives outside the context window, in a file or database.

Bigger is not simply better. Anthropic reports that as the token count grows, recall gets worse, which it calls context rot (Effective context engineering). So the goal is the smallest set of useful tokens, not the biggest window.

Worked example

A student finishes laser cutter training on Monday and returns Thursday.

  1. Monday: the assistant learns "passed laser training". It exists only in Monday's context.
  2. Monday ends. The context is discarded.
  3. Thursday: a new session starts empty. The assistant asks the student to prove their training again.
  4. Fix: a tool save_training(student, machine) writes to a database on Monday, and check_training_record reads it on Thursday.
  5. Rule: facts that must outlive the session go in storage and come back through a tool.
Check yourself

Which fact belongs in storage between sessions, rather than only in context?

Show the answer

The third option, because it must outlive the session.

Retrieval and notes 2 min

A manual may have hundreds of pages. Pasting it all in each call is slow, costly and invites context rot. Instead use retrieval: look up only the few pages relevant to the question and put those in context.

Anthropic describes two timings. Pre-retrieval loads the relevant text before the model runs. Just-in-time retrieval gives the agent a search tool, so it fetches pages while it works. A hybrid is common: some key text up front, the rest on demand (Effective context engineering).

For work that spans many steps, the agent can also keep notes: it writes progress to a file outside the context, such as a to-do list or NOTES.md, and reads it back later, even after the context is cleared or summarized.

Worked example

A student asks, "What speed should I cut 3 mm acrylic on the laser?"

  1. The model calls search_manuals("laser cutter acrylic speed").
  2. The tool searches the manuals and returns the best three paragraphs, not the whole manual.
  3. Those paragraphs enter the context, about a few hundred tokens instead of tens of thousands.
  4. The model answers from them and can cite the page.
  5. The cost is low because the model never saw the other pages.
A common mix-up

"A bigger context window means I do not need retrieval." It is tempting because a window can hold a whole manual. But you pay for every token on every call, and recall degrades as the context fills. Retrieval stays cheaper and often more accurate.

Check yourself

Which design keeps the assistant's cost per request lowest as the manuals grow?

Show the answer

The second option: retrieve a few pages instead of sending everything.

Worked example and practice 2 min

Worked example: sorting what goes where

Decide where "the 3D printer is booked Tuesday 2 pm" should live.

  1. Ask: is it needed after this session? Bookings are, but the calendar already stores them.
  2. So it is not the assistant's own memory; it is read through check_calendar when needed.
  3. Ask: is it needed in every call? No, only when someone asks about it.
  4. Result: calendar tool, fetched on demand, held in context only during that run.
Your turn

Sort these three: (a) the student's name, which they typed this session; (b) the laser cutter's safety rules, 40 pages; (c) "student prefers evening slots". Say for each: context only, retrieval, or saved notes. Step 1 is done for you: ask whether it is needed after this session.

Show a solution

(a) Context only, unless you need it next visit, in which case save it in the student's record. (b) Retrieval: search it and pass in the matching pages. (c) Saved notes: it must outlive the session, and it is small enough to load at the start of the next one.

Summary 1 min

  • The context window is everything the model sees in one call; the program rebuilds it every call.
  • Within a run, the context carries steps forward; across sessions it is empty unless you saved and reloaded something.
  • Retrieval brings in only the pages needed; notes and records carry facts between sessions.
  • Keep context small: it costs tokens on every call and long contexts recall worse.
