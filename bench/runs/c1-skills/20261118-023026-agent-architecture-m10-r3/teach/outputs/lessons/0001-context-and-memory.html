Context and memory in an agent

By the end of this lesson you can say, for any piece of information in the makerspace assistant, whether it belongs in the context window, in saved notes, or in a manual that is searched on demand.

Warm-up 1 min

Recall

In the agent loop, after the program runs a tool the model asked for, what does it do with the result?

Check your answer

It sends the result back to the model as input for the next model call. Today's question is what the model sees on that next call, and what happens when it sees too much.

The context window 2 min

Start with a game. Your character has a backpack with 20 slots. Everything you want to use right now must fit in it. A model works the same way.

The context is all the text the model reads on one call: the system prompt, the tool descriptions, the conversation so far, and every tool result. The context window is the maximum amount of that text, counted in tokens, a model can take in one call. Anthropic describes context as "a finite resource with diminishing marginal returns".

Two limits follow. Cost: you pay for the tokens you send on every call, so a bigger context costs more every step. Quality: the same article says that as the window fills, the model's ability to accurately recall information from it decreases. Anthropic calls this context rot.

Worked example

Costing a three-step request. Say the prompt and tools are 1,000 tokens, each tool result is 500 tokens, and we ignore the model's own output.

  1. Call 1 sends 1,000 tokens (prompt, tools, question).
  2. Call 2 sends those 1,000 plus the 500-token calendar result: 1,500.
  3. Call 3 sends 1,500 plus a 500-token manual page: 2,000.
  4. Total input paid for: 1,000 + 1,500 + 2,000 = 4,500 tokens, not the 2,000 you might guess from the final size.

What is kept, and for how long 2 min

Here is the key fact: the model itself remembers nothing between calls. What feels like memory is the program resending text. This gives three lifetimes.

LifetimeWhere it livesExample
One stepOnly in that call's inputThe text of the current call
One sessionThe message list the program keepsEarlier turns and tool results
Many sessionsStorage outside the model: files or a databaseA student's training status

When a session ends, the message list is gone unless the program saved something. A new session starts with an empty context.

Worked example

Maya books the laser cutter on Monday, then returns on Friday and asks, "Did I finish the safety training?"

  1. On Monday the context held her questions and tool results. The session ended and the list was thrown away.
  2. On Friday a new session starts. The model sees only the system prompt, tools and Maya's new question.
  3. Without saved data, the model cannot know. It might guess, which is worse than saying "I don't know".
  4. Fix: the program reads Maya's record from storage and puts it in the context, or gives the model a tool to look it up.
A common mix-up

"A bigger context window gives the assistant long-term memory." It is tempting because a long chat feels like remembering. But a window only holds one session's text, empties when the session ends, and gets more expensive and less accurate as it fills.

Retrieval: finding the right page 2 min

A manual of 300 pages will not fit, and should not be pasted in anyway. Retrieval means the program fetches only the few passages relevant to this question and puts those in the context.

Anthropic describes keeping lightweight references, such as file paths or links, and loading the data at runtime with tools, instead of loading everything up front. It calls this just-in-time loading.

For your assistant, that is a search_manuals(query) tool. It returns the best-matching passages, so the model reads 500 tokens instead of 150,000.

Worked example

A student asks, "What speed should I cut 3 mm acrylic on the laser?"

  1. The model requests search_manuals("laser cutter acrylic speed 3 mm").
  2. The program searches the manual pages and returns the top three passages, about 600 tokens.
  3. Those passages join the context. The model answers from them and can name the page.
  4. The other 299 pages never cost a token. If the search missed, the model can search again with different words.

Notes: memory between sessions 2 min

Notes are the other half. In note-taking memory the agent writes facts to storage outside the context window and reads them back later. Anthropic describes this as structured note-taking, with a file-based memory tool as one implementation.

When a run gets close to the window limit, a second technique helps: compaction, which summarizes the conversation and starts a fresh context with the summary (same article).

Worked example

Design what to save for the training status.

  1. List what must survive: Maya passed laser safety on 12 March; she has not done the 3D printer course.
  2. Store it as a small record per student, such as {"student": "maya", "trained": ["laser"]}.
  3. Give the assistant tools read_record and save_record.
  4. Next visit, a read call puts about 30 tokens in the context instead of replaying a whole old chat.
  5. Do not save everything: the full chat transcript is expensive to reload and mostly noise.

Practice 1 min

Your turn

Place each item: (a) the rule "never book past 9 pm"; (b) the page on the vinyl cutter's blade depth; (c) a student's allergy to resin, to remember next time. Choose context always, retrieved on demand, or saved notes. Start with (a): it applies on every request.

Show a solution

(a) The rule is short and needed on every call, so it goes in the system prompt, which is always in context. (b) The blade page is needed only for some questions, so it is retrieved on demand. (c) It must survive after the session ends, so it is saved as a note and read back next visit.

Summary 1 min

  • The model remembers nothing between calls; the context is text the program resends, and it grows, costs and degrades.
  • Context lives for a session, so anything needed next visit must be saved outside it.
  • Retrieval loads only the relevant manual passages, just in time.
  • Notes are small records written to storage and read back later.

Say it in your own words: explain to a teammate why we do not just paste all manuals into the prompt, and what we do instead.
