Context and memory

From lesson 1.

Terms

TokenA small piece of text the model works in. Rough estimate for English: characters / 3.5 (varies by model).
Context windowAll the text the model can use for one reply, including the reply (docs).
Message historyEverything said and returned so far; sent again on each call.
Short-term memoryThe history of one session.
Context rotRecall gets less accurate as the context grows.
CompactionSummarize a conversation nearing the limit; start fresh with the summary.
Long-term memoryStored outside any one conversation; available in later sessions.
NoteSaved text or data, loaded back into the context when needed.
RetrievalSearch stored material at run time; add only the relevant parts.
ChunkA small, separately findable piece of a document.

Estimate one request

  • Input = instructions + tool list + notes + history + retrieved chunks + tool results.
  • Input + room for the reply must fit the window.
  • Cost of a visit: add up the input of every call (plus whatever replies cost).

Where each thing goes

InformationPlace
Instructions, tool listEvery call
Student's noteLoad at session start; save changes
Manual textRetrieve when needed
Calendar listingFetch fresh, then clear
Chat historyKeep this session; clear or summarize

Ask: when is it needed, and how fast does it change?

Checks

  • Crowded context: clear used results first, then summarize. Check the summary kept decisions, open problems and important details.
  • Exact code or part number: search by exact words. Different wording: search by meaning.
  • Read retrieved chunks: right machine? really covers the question?
  • Skipping retrieval: does everything fit, and can you afford it on each call?
