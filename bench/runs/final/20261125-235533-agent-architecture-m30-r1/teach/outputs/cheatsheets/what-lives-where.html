What lives where: context and memory

From lesson 1. Token counts in the lesson are illustrative.

The window holds, on every call

System prompt + tool definitions + history (questions, model requests, tool results) + the reply. Everything is counted in tokens and billed.

Cost rule

Each call re-sends the whole history. Total input billed = the sum of every call's full input. Cost grows with steps and with what is carried.

Where each thing goes

ThingHomeReason
System prompt, tool definitionsAlways in contextSmall; they define the assistant
Long manualsRetrieved: a few chunks via search_manualsWhole manual is re-billed every step and read less reliably
Student facts (training, preferences)Saved: memory file or database, read at the startSurvives between sessions
Safety-gating recordsDatabase the program checksDo not rely on a model-written note
CalendarFetched for one machine and weekChanges, so never stored
Old transcripts, raw tool outputNot keptBulky and stale

Between steps vs between sessions

Between steps: the message list in the running program. Between sessions: nothing, unless the program writes it out and reads it back.

Memory file rules

Write facts and decisions. Keep notes short. Read on demand. The model asks; the program does the file work.
